Chiavi esterne e integrità referenziale

Una chiave esterna collega fatti memorizzati in relazioni diverse e impedisce riferimenti a tuple inesistenti.

Pagina 5 di 6 5 di 6
← Superchiavi e chiavi Logico e fisico →

L'idea

La relazione referenziante, detta informalmente figlia, contiene attributi che richiamano una chiave della relazione referenziata, detta genitore.

STUDENTI(Matr, Nome) con PK = {Matr}

ISCRIZIONI(Matr, CodCorso) con FK {Matr} → STUDENTI{Matr}

Ogni matricola presente in ISCRIZIONI deve quindi individuare uno studente esistente. Una riga con Matr = 999 è ammessa solo se esiste lo studente 999.

Definizione formale

Siano:

  • R lo schema referenziato, con chiave candidata K = {A₁, …, Aₘ};
  • S lo schema referenziante, con attributi F = {B₁, …, Bₘ};
  • una corrispondenza Bᵢ ↔ Aᵢ, con domini compatibili, per ogni componente.

In assenza di valori nulli, il vincolo referenziale richiede:

∀t ∈ rS, ∃u ∈ rR: t[B₁]=u[A₁] ∧ … ∧ t[Bₘ]=u[Aₘ]

Equivalentemente, dopo aver allineato i nomi degli attributi, i valori di F presenti in S devono essere inclusi nei valori della chiave K presenti in R.

πF(rS) ⊆ πK(rR)

Perché si riferisce una chiave candidata? Perché il valore referenziato deve individuare al massimo una tupla. In SQL, per portabilità, si riferiscono colonne dichiarate PRIMARY KEY oppure UNIQUE.

Foreign key opzionale e NULL in SQL

Una foreign key è obbligatoria quando tutte le sue colonne sono NOT NULL. Se una colonna può essere NULL, il riferimento può essere assente.

Per una foreign key composta SQL distingue il modo in cui vengono trattati i nulli:

Semantica dei nulli in una FK composta
ModalitàComportamento
MATCH SIMPLEÈ la modalità predefinita: se almeno un componente è NULL, la riga non deve trovare una corrispondenza.
MATCH FULLAmmette l'assenza del riferimento solo quando tutti i componenti sono NULL; una combinazione parzialmente nulla è rifiutata.

Il supporto a MATCH FULL varia tra DBMS. Per un legame obbligatorio e portabile, la scelta più chiara resta dichiarare tutte le colonne NOT NULL.

FK composte e auto-riferite

Composta

APPELLI(CodCorso, Anno, Data) può riferire CORSI_ANNUALI(CodCorso, Anno). La corrispondenza riguarda la coppia, non i due valori separatamente.

Auto-riferita

CATEGORIE(Id, Nome, IdPadre) può avere IdPadre → CATEGORIE(Id). Un IdPadre nullo può rappresentare una categoria radice.

Che cosa accade quando cambia il riferimento?

Le azioni referenziali stabiliscono come reagire a un DELETE o a un UPDATE della chiave referenziata.

Azioni referenziali principali
AzioneEffettoQuando ha senso
RESTRICT / NO ACTIONRifiuta l'operazione se produrrebbe riferimenti invalidi.Scelta prudente quando i dati figli devono essere gestiti esplicitamente.
CASCADEPropaga la cancellazione o il nuovo valore alle righe referenzianti.Quando la riga figlia non ha significato autonomo.
SET NULLRimuove il riferimento impostando a NULL le colonne interessate.Solo se le colonne sono nullable e l'assenza ha un significato corretto.
SET DEFAULTImposta il valore predefinito, che deve comunque soddisfare il vincolo.Raro e non supportato da tutti i DBMS.

Dettaglio implementativo: la differenza temporale tra RESTRICT e NO ACTION dipende dal DBMS e dalla possibilità di differire i vincoli. In MySQL/InnoDB le due azioni hanno effetto immediato equivalente.

Esempio SQL completo

CREATE TABLE Studenti (
  Matr  INTEGER     PRIMARY KEY,
  Nome  VARCHAR(50) NOT NULL
);

CREATE TABLE Iscrizioni (
  Matr       INTEGER     NOT NULL,
  CodCorso   VARCHAR(20) NOT NULL,
  PRIMARY KEY (Matr, CodCorso),
  FOREIGN KEY (Matr)
    REFERENCES Studenti (Matr)
    ON DELETE RESTRICT
    ON UPDATE RESTRICT
);

Verifica rapida

In una FK composta (A, B) con la modalità predefinita, la coppia (NULL, 7) deve trovare una riga referenziata?

Controlla la risposta

No: con MATCH SIMPLE la presenza di almeno un componente nullo sospende il controllo per quella riga. Con MATCH FULL, invece, la coppia parzialmente nulla sarebbe rifiutata.
